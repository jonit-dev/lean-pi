## Solution

Five surgical fixes, all in LeanPi's own code. Nothing in `node_modules` is edited: a pnpm patch would not reach npm installs of `leanpi`.

1. **Route skip for external runners.** In `registerSubagentRouting`, resolve the target agent through pi-subagents' own discovery (`discoverAgents` / `resolveAgentName`, `pi-subagents/src/agents/agents.js:417,2630`). Return early when `runner.type` is not native Pi. Also skip workflow steps that target such agents. Do not maintain a hardcoded name list.
2. **Card title.** The header shows `Subagent <Name>: <Model> (<Effort>)`. *Name* is the agent's name when the call gives one (`reviewer`, `claude-code`). Otherwise it is a call sign given in spawn order within the session (Alpha, Bravo, Charlie…). *Model* and *Effort* come from the resolved `input.model` (`provider/id:level`, after routing) through the model registry's display name. For an external-CLI agent, use its runner label (e.g. `Claude Code`) and omit effort when there is none. Implement this in LeanPi's existing compact-UI adapter layer, as a `renderCall` override or a pi-subagents render hook, whichever the adapter already uses for other tools. Do not fork `pi-claude-code-ui`.
3. **`/dev/*` redirects.** In `classifyCommand`, do not treat `/dev/null`, `/dev/stdout`, `/dev/stderr`, `/dev/stdin`, `/dev/tty` or `/dev/fd/N` as `external_dir`. Only these exact targets are exempt. Any other `/dev/…` path still classifies as external.
4. **Empty-output bash results.** In `src/cli/background.ts` (the adapter that owns `pi-patty-bg-tasks`), wrap the bundled `bash` tool's `execute`:
   - An error whose message is exactly `(no output yet)` becomes `Command failed (non-zero exit) with no output`.
   - A success whose only text is `(no output yet)` becomes `(no output)`.
   - The exit code is not recoverable at this layer. Filing an upstream issue on `pi-patty-bg-tasks` to keep it is a follow-up, not a box.
5. **Empty CLI result = failure.** In `harness.ts`, when the summary is empty, no structured output was requested, and `changedPathsSince` found no changes, return `status:"failed", failure:"exit"` with the last 300 chars of stderr (`failureReason` already formats this). An empty summary *with* file changes keeps today's `ok`.

Risks: (1) a wrong runner lookup would silently stop routing native children. The AC therefore asserts both sides. (3) must not open other `/dev` paths. The AC asserts `/dev/sda` still classifies as external.

## Decisions

- 2026-09-27 (Claude, assumption, safe to reverse): the call sign ("Bravo") is used only when the call names no agent. A named agent shows its own name. Confirm with the operator at Phase 1 checkpoint.
- 2026-09-27 (Claude, follows from the code, not reversible at will): the card is a **source** entry (`extensions/subagent-card/index.ts`) attached after the compact UI, not a patch from `dist/`. A compiled `.js` extension is imported by Node, so it gets this package's own copy of `pi-coding-agent` and would patch a prototype nothing renders with — the trap `src/cli/spinner.ts` and `src/cli/fold-cache.ts` already carry. The entry passes the prototype in; every decision, and the card's shared state, stays in `dist/`.
- 2026-09-27 (Claude, open): the operator has not confirmed the call-sign assumption above. The card is the only place it shows, and it is a one-line change in `src/subagents/card.ts` if they want a different rule.
- 2026-09-27 (Claude, correction pass, ceiling named): the card edit is the package's own row with its summary swapped, not a redrawn line — redrawing is what dropped the live status dot. It reads the line out of the row's component through one field the package keeps private to it, and hands the row back untouched when that field is not a string (a version that renames it falls back to `Subagent Subagent`, no crash). Raise it upstream (`pi-cc-tools` has no public per-tool label hook) if the coupling ever bites.
